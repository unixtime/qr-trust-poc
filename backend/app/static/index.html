Open the lab first. Do not use the native camera as the verifier.

The generated QR contains the signed payload itself. If you scan that QR with the iPhone Camera app, the phone opens the payload URL directly and bypasses verifier checks. The intended test path is the browser lab at /verifier/lab.

Why your screenshot failed

Safari was trying to open acme.example, which is the QR payload in the demo scenario. That domain is intentionally a placeholder, so native scanning shows “server can’t be found.”

Correct phone flow

1. Open this server in Safari. 2. Open the verifier lab. 3. Generate a QR. 4. Either use Verify current QR without scanning, upload the QR image, or scan the QR with the lab camera from a second screen.

What desktop camera scan means

A laptop camera cannot scan the QR that is being displayed on the same laptop screen. Show the QR on your phone or another monitor, or use image upload or direct verify instead.

Safari camera limitation on LAN HTTP

If you open the lab over plain http://192.168..., Safari may not expose getUserMedia. In that case the lab should tell you to use image upload or direct verify instead. For true camera scanning in Safari, serve the lab over HTTPS.

Phone Test Steps

  1. Open /verifier/lab on the phone.
  2. Enter the admin token if the lab asks for it and issue a verifier API key.
  3. Select a scenario and click Generate demo QR.
  4. For the fastest test, click Verify current QR without scanning.
  5. To test QR decoding, upload the QR image or scan it from a second device.
  6. Repeat the same verification to confirm replay blocking.

Expected Scenarios

Valid first scan

First verification should be accepted. Running the same verification again should block as replay.

accepted, then replay_guard
Expired credential

The verifier should reject the code before nonce consumption because the time window is already closed.

time_window
Revoked certificate

The verifier should reject the envelope before replay reservation because certificate status is not valid.

certificate_status
Subdomain allowed

A payload under a verified parent host should pass when subdomain matching is enabled.

accepted
Subdomain blocked

The same payload should fail when the verifier is configured to require exact host matching.

payload_revalidation
Payload mismatch

A payload outside the issuer’s current verified domain set should fail even when the signature is valid.

payload_revalidation
